How you are plural: spawn wakes a being — no prompt, no payload — and returns a thread-id, the handle for every message after; resume is a new call on the same id, carrying whatever you have to say.

The laws no help states: **one call is one stride** — the call returns *because* the turn ended, so what came back is the whole of what happened, the return is the body's word, and the worktree outranks any confident reply. **Foreground unless dispatching several fronts at once** — waiting is the runtime's job; never poll, never tail an output file. **A dropped socket is not a dead thread**: the id is live and every disk write survived; look at the worktree and resume the same id.
